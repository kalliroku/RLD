# Mediator — RL 포지셔닝 판정

## 양측이 공통으로 짚은 진실

라운드 1 옹호문에서 양측이 명시적으로든 암묵적으로든 공유하는 사실이 셋 있다.

1. **현재의 정체성 혼란은 더 이상 미룰 수 없다.** A 도 "한 줄 정체성"이 필요함을 인정하고, B 도 README/GDD/devlog 3중 정체성을 해체해야 한다고 주장한다. "RL 교육 도구 + 메이커류 + 로그라이크" 3중 포지셔닝은 둘 다 폐기 대상.
2. **알고리즘 15종은 자산이지 부채가 아니다.** A 는 "튜닝 깊이"의 재료로, B 는 "캐릭터 시그니처"의 재료로 쓴다. 양측 모두 알고리즘을 *드러내는* 방향이며 *숨기는* 방향이 아니다.
3. **시뮬레이터 결과 (수동 100배 저렴, HybridPlayer 29.5/31)는 무시할 수 없는 데이터다.** A 는 "버그", B 는 "진실"로 해석이 갈리지만, 양측 모두 이 측정값을 디자인 결정의 닻으로 삼는다.

## 양측 약점 — 옹호자가 인정하지 않은 부분

**A 가 회피한 부분**: A 의 수술 수치 (스텝당 식량 5배 + 운영비 1/3 + MAX_EPISODES 1/5 + CONVERGENCE_THRESHOLD 0.85) 는 **시뮬레이터 검증이 0회**다. 즉 "0.6~1.7배 영역으로 무너진다"는 *모델 없는 예측*. Phase E-1 시뮬레이터가 발견한 100배 격차는 4전략 × 10회 × HP-aware BFS 로 측정한 *실측*이었다. A 는 자기 입장을 데이터로 정당화하면서, 정작 자기 처방의 효과는 데이터로 검증하지 않은 채 던졌다. 더 무거운 빈틈은 *수술 후에도 자기 약점 단락이 말한 "온보딩 5분 학습 대기"가 그대로 남는다*는 것이다. 이코노미를 고쳐 격차를 1배로 만들어도, 8시간 세션의 동사는 여전히 "Instant 누르고 Q-table 채워지는 걸 본다"이다 — B 의 최강 펀치는 "이코노미 수술 후 플레이어가 실제로 하는 행위"를 묻는 것이었고 A 의 답은 *튜닝 슬라이더*인데, 이건 본질적으로 hyperparameter sweep 노가다라는 B 의 반박을 A 가 무시했다.

**B 가 회피한 부분**: B 의 시드 모디파이어 7종 (미끄러운 바닥, 두 명만, 안개 짙음, 인색한 길드 등) 은 **이미 가진 자산으로 가능**해 보이지만, 실제로는 (a) `useHpState`/`slippery` 류 던전 옵션과 (b) RunState 의 hire/budget 제약과 (c) renderer 의 fog 시스템에 *각각* 들러붙어야 하는 횡단 변경이다. B 가 "공수 추가로 든다"고 한 줄 인정하고 넘어간 부분이 실제로는 *데이터 모델 + 학습 큐 + UI 가 다 흔들리는 일*. 또한 B 의 가장 큰 빈틈은 **알고리즘이 캐릭터로 격하되는 순간 시드 변형 위에서 알고리즘 차이가 *덜* 보인다**는 것이다. 시드 변형이 의사결정 공간을 흔들면 Q-table 가치는 떨어지고 BFS 휴리스틱이 다시 우위에 선다 — B 가 약속한 "다이나는 빠르게 재계획, Q군은 무력"의 차이는 한 런 안에서 체감되기에 너무 미세하다 (StS 의 빌드 시너지처럼 *런 동안 누적*되지 않는다). 즉 B 의 알고리즘=캐릭터 비유는 *StS 의 4 캐릭터 = 4 게임*에 비해 메커니즘 분기 폭이 한 자릿수 작다.

## 결정의 무게중심

진짜 load-bearing 한 질문은 "출시 게임 8시간 동사가 무엇인가" 도, "어느 시장 사례가 더 맞는가"도 아니다. **"솔로 개발자가 6개월 안에 출시 가능한 핏 (fit) 이 어느 쪽인가"** 가 무게중심이다.

- A 노선: 이코노미 수술 3~5일 + 시뮬레이터 재검증 1주 + 하이퍼파라미터 UI 1~2주 + 학습 시각화 강화 1~2주 + Instant/sparkline 온보딩 1주 = **3~5주, 그리고 검증된 적 없는 가정 위**.
- B 노선: 모디파이어 시스템 + 시드 챌린지 UI + PCG 재활용 레이어 + 31던전 밸런스 회귀 = **6~10주, 단 매 단계가 데이터로 검증 가능 (시뮬레이터 동일 사용)**.
- C 노선 (제3안): A 의 이코노미 수술을 *축소된 형태로 채택* (수동 비용만 2~3배, AI 운영비는 손대지 않음) + B 의 모디파이어 시스템 *MVP 3종만 도입* (미끄러운 바닥/두 명만/안개 짙음) + 알고리즘=캐릭터 카피로 재명명, *하이퍼파라미터 슬라이더와 가차는 둘 다 컷*. **4~6주, A/B 양측의 검증된 자산만 채택**.

## 판정

**C — 제3의 길 (RL 양념 + 이코노미 보정)**

근거 1 — **시뮬레이터 데이터에 더 충실한 것은 B 의 해석**이다. 100배 격차는 4전략 × HP-aware BFS 로 측정된 실측이고, A 의 "수술하면 1배로 떨어진다"는 *반증되지 않은 가정*이다. 데이터를 부정하는 디자인은 디자인의 책임이 더 크다.

근거 2 — **솔로 개발자 출시 시간**: B 가 약속하는 매 런 변주는 기존 PCG + 31던전 + RunState 자산을 *재배선*하는 일이고, A 가 약속하는 "AI 가 정공법" 세계는 *수술 → 재검증 → 온보딩 재설계 → 마스터리 시스템 신규 구축*의 4단 사슬이다. 둘 다 6개월 안이지만 B 의 매 스텝이 출시 가능한 부분 결과 (= 1주차에도 시드 챌린지는 작동) 인 반면 A 는 마지막 사슬까지 완성되지 않으면 코어 동사 자체가 비어 있다.

근거 3 — 그러나 **B 를 그대로 채택하면 "수동이 정공법"이 너무 강하게 굳는다**. 시뮬레이터의 100배 격차는 *받아들이되 절반으로 줄여야* 마스터리 곡선 후반에 AI 가 의미를 가진다. 따라서 A 의 이코노미 수술 중 *수동 식량 비용만* (스텝당 1→2~3) 채택, AI 측은 손대지 않는다. 수술 1 만 가져가고 수술 2/3 는 컷.

근거 4 — **알고리즘 = 캐릭터 격하는 B 가 정답**, 하지만 그 격하가 *알고리즘 다양성을 숨긴다*는 뜻은 아니다. ACT1_SUMMARY 에 이미 박혀 있는 성격 카피 ("낙관적 멍청이", "겁쟁이", "공상가") 를 1차 라벨로, 알고리즘 학명은 hover 툴팁으로. A 의 "Q-value 히트맵·정책 화살표 디폴트 ON" 도 함께 채택 — 이건 양념의 *시각적 시그니처* 로서 정합.

근거 5 — **하이퍼파라미터 슬라이더와 가차는 둘 다 컷**. 슬라이더는 B 의 hyperparameter sweep 노가다 반박이 정확하고, 가차는 retention 크리틱이 이미 "결함을 덮는 패턴"으로 진단했다. 두 옵션의 공수를 모디파이어/PCG 에 합산한다.
