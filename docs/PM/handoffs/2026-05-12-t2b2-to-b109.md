## 3. B-109 본진 명세

### 3.1 목적

핸드오프 act1-to-t2b §4.1: "HybridPlayer 가 모디파이어 3종 추가 후에도 25.5/27 ± 2 영역에 유지되는지 측정". T2B-2 까지는 캠페인 모디파이어가 없어서 modifier-off 측정만 가능했음. B-109 = sim 측에 ModifierSet 통합 후 *modifier-on* 측정.

다만 D-2026-05-12-9 로 모디파이어가 데일리 전용으로 축소되었으므로, B-109 의 본래 목적은 변형됨:
- **변형 A (권장)**: sim 의 캠페인 시나리오에 모디파이어 분기를 *옵션으로* 추가하고 (단순 측정 도구로서), modifier-on 일 때도 25.5/27 ± 2 영역에 있는지 측정. 캠페인 출시 시 모디파이어 확장 시 안전성 확보.
- **변형 B**: 데일리 전용이므로 캠페인 sim 회귀는 modifier-off 만 측정하면 충분 — B-109 를 *modifier-off 5×20-run 정기 회귀* 로 격하.

다음 에이전트는 변형 A 를 선택 (M4 의 12종 확장 시 safety net). 변형 B 로 가려면 사용자 동의 필요.

### 3.2 작업 분해 (변형 A)

#### B-109.1 — sim 측 ModifierSet 통합 (~0.3일)

`sim/strategies.js` / `sim/simulator.js` 에 modifier 옵션 분기 추가:
- **slippery (30%)**: simulator 의 `executeTurn` 의 이동 의도 단계에서 30% 옆길 분기. seeded RNG (모디파이어 활성 시 strategy 가 가진 seed 사용)
- **heavy_fog**: HybridPlayer 의 humanSteps 추정 (현재 humanSteps = 단순 경로 + 추정) 에 +20~30% 페널티
- **two_only**: strategy 가 캐릭터 선택 시 풀을 2명으로 제한 (시드 결정). HybridPlayer 의 캐릭터 매칭 로직 (현재 dungeon → character 매핑) 에서 풀 외 픽 시 fallback

`web/js/game/modifiers.js` 는 이미 sim 에서 import 가능 (Node ES module). 단 `Action` import 는 agent.js 에서 가져오므로 잘 작동하는지 확인.

#### B-109.2 — modifier-on 측정 (~0.2일)

```bash
# off baseline (이미 측정됨)
node sim/run-balance.js 20 HybridPlayer

# on, 모디파이어 1종씩
node sim/run-balance.js 20 HybridPlayer --modifier=slippery
node sim/run-balance.js 20 HybridPlayer --modifier=heavy_fog
node sim/run-balance.js 20 HybridPlayer --modifier=two_only

# all combined
node sim/run-balance.js 20 HybridPlayer --modifier=slippery,heavy_fog,two_only
```

각 측정 결과를 BACKLOG B-109 행에 박제.

#### B-109.3 — 통과 기준

- 모디파이어 *없음* (baseline): 24.6 ± 1.5 (현재) → 변동 없음
- 모디파이어 *각 1종*: 23.5 ~ 27.5 영역 안 (loss 가 어느 정도까지 허용되는지는 사용자 확인 필요할 수 있음)
- 모디파이어 *3종 합산*: 영역 이탈 가능 — 그 경우는 D-2026-05-12-9 의 "데일리 전용" 결정으로 정당화 (캠페인은 이 조합 미사용)

### 3.3 작업 비용

총 ~0.5일 (sim 통합 + 측정 + BACKLOG/STATUS 동기화).

## 4. 위험 / 함정 (T2B-2 후 갱신)

기존 act1-to-t2b 인계 §8 + t2b1-to-t2b2 §4 모두 유효. 추가:

### 4.1 modifier RNG 와 학습 stochasticity 의 경계

- modifier.slippery 는 `mulberry32(seed ^ SALT)` 사용 — 데일리 결정론 핵심
- agent / nn / ppo 의 `Math.random()` 은 그대로 (D-2026-05-12-4 verdict: 학습 stochasticity ≠ 세계 생성)
- B-109 sim 통합 시 sim 의 randomness 와 modifier 의 seeded RNG 가 섞이지 않도록 주의. sim 도 별도 seed 받아서 reproducible 회귀가 가능하면 더 좋음 (단, 이번 작업의 의무 아님)

### 4.2 visibilityRange 의 default=5 가 legacy 와 동일한지 확인

- agent.js `getVisibility` 의 선형 감쇠 (`1 - turnsSince/5`) → 1.0/0.8/0.6/0.4/0.2 → 정확히 legacy 와 동일
- 이미 측정으로 확인 (modifier-off 캠페인 sim 24.6/25.6/24.9/25.4/24.1 — T2B-1 baseline 25.0 과 통계적 동일)

### 4.3 two_only 의 캐릭터 풀 = 비-숨김 전체 (14명, scout 제외)

- D-11 로 캠페인 hire 상태 무관. 만약 future 에 NG+ 에서 일부 알고리즘 잠금이 들어가면 이 결정 재검토
- scout (HIDDEN_CHARACTERS) 은 풀에서 제외됨 — 캐릭터 카드 아이콘 미정의 상태라 데일리 picker UI 에 노출 어려움. 유지

### 4.4 캠페인 모디파이어 미진입 위험

- 현재 modifier-band 가 `currentMode === 'daily'` 일 때만 표시. M4 캠페인 모디파이어 도입 시 이 가드 제거 필요
- main.js `_renderModifierBand` 의 mode 체크 line 보면 됨

### 7.1 `/commit` 스킬 정착

`.claude/skills/commit/SKILL.md` 신규 — RLD 컨텍스트로 이식한 commit 워크플로우. caveduck `/commit` 의 골격 차용, 다음 차이점:
- 리뷰어: `code-reviewer` → `korean-git-reviewer` (RLD 의 유일한 리뷰 에이전트)
- 메시지 컨벤션: Conventional Commits 비사용, **영문 imperative + 한국어 body** (직전 RLD 스타일 보존)
- Critical 범주: D-2026-05-12-4 정체성 / D-8 격리 / AI 비용 상수 / 25.5/27 ± 2 발란스 위반
- 메타 자기참조 멘트 금지 (사용자 메모리 룰 반영)

**사용 방법**:
```
/commit                 # 메시지 자동 생성 + 확인
/commit <메시지>        # 메시지 직접 지정
```

매 커밋에 `[reviewed]` 마커가 제목 끝에 박힘. 향후 `/push` 같은 자동화 도입 시 재리뷰 스킵 hook 으로 활용.
