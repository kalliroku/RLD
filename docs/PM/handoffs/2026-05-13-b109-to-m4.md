### 비-자명 결정 (DECISIONS.md 박제)

- **D-2026-05-13-12**: sim 측 modifier.slippery 는 manual-play approximation 으로만 적용. 알고리즘 측 deflection 미적용. **사유**: 15개 알고리즘 파일이 모두 `agent.getNextPosition(intendedAction)` 으로 gold/monster 추적 키를 만들고, deflection 후 `agent.x/agent.y` (실제 위치) 로 grid.tiles 수정 → episode 종료 시 restore loop 가 의도 위치를 복원하려다 OOB 인덱스 (`tiles[-1][x]`) 로 TypeError. 캠페인은 modifier 무활성 + 데일리 PCG 던전은 gold/monster 미배치라 production 에서는 latent. M4 캠페인 모디파이어 도입 시 일괄 수정 필요.

## 3. M4 진입 전 정리 필요 항목

### 3.1 D-12 algorithm deflection 버그 (블로커 for 캠페인 모디파이어)

**위치**: 15개 알고리즘 파일의 episode loop. 패턴은 다음과 같음 (`sarsa.js:160-180` 가 대표적):

```js
// 의도 위치 기반 키 만들기 (deflection 미고려)
const nextPos = agent.getNextPosition(action);
const nextKey = `${nextPos.x},${nextPos.y}`;
const originalTile = this.grid.getTile(nextPos.x, nextPos.y);  // OOB 가능

if (killedMonsters.has(nextKey) && originalTile === TileType.MONSTER) {
    this.grid.tiles[nextPos.y][nextPos.x] = TileType.EMPTY;  // OOB 가능
}

const result = agent.move(action, this.grid);  // deflection 가능

if (result.tile === TileType.GOLD && !collectedGold.has(nextKey)) {
    collectedGold.add(nextKey);  // 의도 위치 키 추가 (잘못된 위치)
    this.grid.tiles[agent.y][agent.x] = TileType.EMPTY;  // 실제 위치 수정
}

// ...episode 끝...

for (const key of collectedGold) {
    const [x, y] = key.split(',').map(Number);
    this.grid.tiles[y][x] = TileType.GOLD;  // 잘못된 위치 복원 → 더 큰 문제
}
```

**수정 방향**:
- `move()` 호출 후 `agent.x/agent.y` (실제 위치) 기반으로 키 재생성
- 또는 `agent.move()` 가 `actualNextPos` 를 result 에 포함하도록 인터페이스 확장
- 또는 grid.tiles 수정을 episode-local 으로 격리 (deep copy)

**영향 파일** (대략):
- `qlearning.js` / `sarsa.js` / `sarsa-lambda.js` / `expected-sarsa.js` / `monte-carlo.js`
- `dyna-q.js` / `double-qlearning.js` / `qv-learning.js` / `actor-critic.js`
- `reinforce.js` / `tree-backup.js` / `prioritized-sweeping.js` / `acla.js` / `ensemble.js`
- `local-qlearning.js`

공수: 0.5~1일 (패턴 동일).

### 3.2 캠페인 모디파이어 도입 시 발란스 재검토

B-109 측정은 modifier-off baseline 보장 + slippery/heavy_fog 단독 안전성만 확인. M4 12종 도입 시:
1. 새 모디파이어마다 단독 20-run 측정 (영역 [23.5, 27.5] hit 확인)
2. 합산 2~3종 스택 측정 (캠페인 던전마다 1~3종 활성 시 예상)
3. two_only 류 (캐릭터 풀 제한 모디파이어) 는 캠페인 도입 비추천 — 13.3/27 으로 큰 영향

### 3.3 modifier-band UI 가드 제거

`web/js/main.js _renderModifierBand` 가 `currentMode === 'daily'` 체크. M4 캠페인 모디파이어 도입 시 이 가드 제거 또는 mode 확장 필요.
