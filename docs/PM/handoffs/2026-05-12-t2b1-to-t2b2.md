## 2. T2B-1 산출물의 T2B-2 hook

### `dailyContext.modifierIds`

`getDailyChallenge(date)` 가 `{ dateKey, seed, modifierIds: [] }` 를 반환. **현재 modifierIds 는 항상 빈 배열**. T2B-2 진입 시 다음 두 곳을 갈아끼우면 끝:

1. `daily-mode.js` 의 `getDailyChallenge` — 시드 기반 `pickModifiers(seed, 1)` 호출 결과를 modifierIds 로 채움.
2. `main.js` 의 `enterDailyMode → renderDailyIntro` — 이미 modifierIds.length > 0 일 때 `#daily-modifiers-row` 를 unhide 하도록 작성됨. 추가 작업 X.

핸드오프 §3.4 (T2B-2.4) "시드 ↔ 모디파이어 연결" 의 절반 이상이 이미 박혀있다.

### `dailyHistory.recordAttempt(dateKey, { ..., modifierIds })`

기록 객체에 `modifierIds` 필드가 이미 포함됨. T2B-2 진입 후 modifierIds 채워서 호출하면 자동 영속화.

### 모디파이어 띠 UI 자리

핸드오프 §3.3 (T2B-2.3) "모디파이어 띠" — 현재 데일리 패널 안에 `#daily-modifiers-row` 만 있음. 캠페인 런에 적용되는 모디파이어 띠 (게임 상단) 는 별도 div 신설 필요. 위치 후보: `<div class="game-area">` 의 canvas 위 (briefing-overlay 와 같은 stacking).

## 3. T2B-2 본진 명세

이 문서의 §3 은 act1-to-t2b 인계 §3 와 동일. 상세 작업 분해는 [`./2026-05-12-act1-to-t2b.md`](./2026-05-12-act1-to-t2b.md) §3 참조 — 변경 없음, 다만 §3.2 의 작업 비용 표가 갱신:

| 모디파이어 | 효과 | 구현 비용 (T2B-1 후) |
|---|---|---|
| **미끄러운 바닥** (slippery) | 이동 방향이 30% 확률로 옆으로 빗나감 | **저** — `slippery: true` flag 이미 일부 던전 존재. 런타임 ModifierSet 으로 격상만 하면 됨 |
| **두 명만** (two_only) | 한 런에서 사용 가능한 세르파를 2명으로 제한 | **중** — 캐릭터 선택 UI 락 + run-state.hiredCharacters 제한. **데일리에서는 시드 기반 자동 2명 픽** (rng.js 의 mulberry32 재사용) |
| **안개 짙음** (heavy_fog) | fog 가시 범위를 N → N/2 | **저** — `agent.js getVisibility` 보정. 캠페인 + 데일리 양쪽에 적용 |

## 4. 위험 / 함정 (T2B-1 후 갱신)

기존 act1-to-t2b 인계 §8 모두 유효. 추가:

### 4.1 데일리 + 캠페인 분리 위반 위험
- T2B-2 의 slippery / two_only 모디파이어가 캠페인 발란스에 영향 → B-109 회귀 필수.
- 단, **데일리 모드에서는 캠페인 발란스 무관** — D-2026-05-12-8 보장.

### 4.2 시드 결정론 깨질 위험
- 만약 ModifierManager 내부에서 `Math.random()` 을 쓰면 데일리 결정론 파괴. **반드시 `mulberry32(seed)` 만 사용**.
- AI 측 (agent / nn / ppo) 의 `Math.random()` 은 그대로 둠 — D-2026-05-12-4 verdict 의 *학습 stochasticity ≠ 세계 생성* 원칙.

### 4.3 데일리 패널 레이아웃 wrap
- `.container { max-width: 1000px }` 때문에 데일리 패널이 캔버스 아래로 wrap 됨 (캠페인 .controls 와 동일 동작). 의도된 동작. 모바일 fit-to-screen (B-201) 작업 시 같이 다룰 영역.
